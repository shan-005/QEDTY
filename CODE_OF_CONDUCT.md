# Code of Conduct

## Our standard

Seraph Guard is intended to be a technically rigorous and welcoming open-source project.

Participants are expected to:

- be respectful and professional;
- discuss technical disagreements in good faith;
- focus criticism on ideas, implementations, evidence, and behavior rather than people;
- welcome constructive questions;
- respect different levels of experience;
- protect confidential and sensitive information;
- follow applicable laws and project security policies.

## Unacceptable behavior

The following behavior is not acceptable:

- harassment or discrimination;
- threats or intimidation;
- personal attacks;
- deliberate disruption of project infrastructure;
- publishing another person's private information;
- publishing confidential security reports;
- malicious manipulation of project infrastructure;
- knowingly introducing malicious code or backdoors;
- abuse of project communication channels;
- repeated bad-faith conduct.

## Security-specific conduct

Security research and responsible disclosure are welcome.

However, security reports must follow `SECURITY.md`.

Do not publicly disclose an undisclosed vulnerability merely to attract attention to a report.

Do not use Seraph Guard's public infrastructure to attack systems you do not own or have explicit authorization to test.

## Enforcement

Project maintainers may take reasonable action in response to unacceptable behavior, including:

- requesting corrective behavior;
- removing or moderating content;
- closing discussions or issues;
- restricting participation;
- removing contributions that violate project rules;
- suspending or banning participation in project spaces where necessary.

Enforcement decisions should be proportionate to the behavior and focused on protecting the project and its community.

## Reporting

If you need to report conduct that cannot safely be handled publicly, contact the project maintainers through a private channel available through the repository or its organization.

Do not use the public issue tracker to disclose private security vulnerabilities.

## No retaliation

Good-faith reports of misconduct or security issues should not result in retaliation.

## Changes

This code of conduct may be updated as the project and community evolve.
